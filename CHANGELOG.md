# Changelog

## Unreleased
- Scope-owning nodes (Function, If, Else If, While, For, Match) now show one
  scope pin per registered local variable, labelled with the variable's name,
  and always keep one fresh empty "add scope" slot for the next variable.
- A Get Variable node spawned from a node's input pin is placed one level
  (column) farther left of the node that uses it.

Unreleased
- **Performance: smoother panning / zooming and a cheaper script open.** (1) The wire overlay (`WireHighlight`) used to measure every connection of the graph on every frame, and repaint every wire whenever anything moved; once it existed (after the first right-click menu or wire click) that made panning sluggish on larger graphs. It now watches only scroll offset, zoom and size per frame, repaints when a node moves / resizes / is rebuilt (`_mark_wires_dirty`, fed by the views' `position_offset_changed` / `resized`, `_sync_connections` and the Error / Warning nodes), computes the canvas transform once per repaint and skips wires that lie entirely outside the visible area. (2) Opening a script re-scanned the whole project on every open: both registries re-parsed the 147 KB API dump, re-walked ClassDB and re-read every project script. Engine-side entries are now collected once per editor session and replayed, and a project script is re-parsed only when its modified time changes (`func_registry.gd`, `type_registry.gd`); the set of entries is the same as a cold scan. (3) The debounced error / warning check no longer starts while a mouse button is held (it re-arms 0.3 s later), so it cannot compile in the middle of a pan or drag. (4) The status line after opening a script now reports the load time split into registries / graph / dock. Not yet run in the engine.
- **Comment nodes fit their text.** A comment used to wrap at a tiny width and then keep a tall, mostly empty node. It is now as wide as its longest line (up to 360 px, then it wraps) and exactly as tall as the wrapped text needs, and it shrinks again when the text gets shorter. Node: `_fit_comment_size`. Not yet run in the engine.
- **Comment nodes have no pins.** A Comment is plain text, so it no longer shows an execution input pin (`exec_in` is false for `Kind.COMMENT`). Comments inside a function body are still kept in order: generation walks the same hidden links as before, so scripts round-trip unchanged; a comment simply cannot be wired by hand any more. Not yet run in the engine.

When a script is loaded, an Operator operand or an If / Else If condition that is just a declared variable's name (`ratio >= 0.85`, `if ready:`) is now fed by a **Get Variable** node wired into the pin instead of the name sitting on the pin as text; the generated source is identical. - **Fix: `if mod.is_valid():` was not connected to a call node.** An If / Else If whose condition is a single method call on a typed loop variable (`for mod: Callable in modifiers:` then `if mod.is_valid():`) kept the call as raw text on the condition pin, so there was no node to see or wire. The owner must be a typed loop variable and the method must exist on that type and return a value; anything else (untyped loop variable, `a.b() and c.d()`, void methods) stays verbatim on the pin as before. `Callable` is now one of the built-in types listed in the node menu (`call`, `bind`, `is_valid`, ...). - **Lambda & Class Reference stability pass (for people who do not write code).** Every refused edit now says why in plain words (status bar), keeps the previous value, and the text box goes back to the value that is really in use once you leave it. Lambda: parameter names cannot be GDScript reserved words (`class`, `func`, `if`, ...) or duplicates; parameter and return types accept typed containers such as `Dictionary[String, int]` but refuse stray spaces / `=` / `;`; a default must be one value (`1, 2` is refused, `[1, 2]` and `"a, b"` are fine); bodies written with spaces or mixed tabs/spaces are converted to tab levels so they compile; renaming a parameter follows into the body (whole words only) and into later parameter defaults. Class Reference: the class must be a name (inner classes `Outer.Inner` allowed) or a `res://...gd` path - spaces, line breaks, `;` and calls are refused instead of corrupting the generated script; an unknown but well-formed class is applied with a "check the spelling" hint; the Instance Source must be a single balanced expression; a member only attaches to a reference of its own class or a subclass (`rotate` of Node2D does not attach to a Control reference; a base-class member fits a subclass reference) - wiring into an occupied slot is checked first so a refused wire never unregisters the member already there, and retargeting a reference away from a registered member's class is reported at generation; deleting a member now removes its slot row on the Class Reference (it used to leave a dead pin); wires and registrations that would make a node depend on itself (a member feeding its own reference's instance input) are refused as loops; problem messages for members now read as instructions ("'queue_free' does not know which object to act on. Connect a Node to its Target pin, or attach it to a Class Reference set to Instance."). Model: `_check_param_name` / `_check_type_text` / `_check_single_expr` / `_check_class_target` / `_normalize_lambda_indent` / `_member_fit_problem` / `_depends_on`. Tests: lambda_tests_cli.gd 122 -> 161 checks, class_ref_tests_cli.gd 80 -> 108 checks (the registration tests now attach members to a compatible reference).
- **Lambda (Callable) nodes.** Inline `func(...) -> T:` literals are now nodes: a **Lambda** node (new `Kind.LAMBDA`, teal header, Functions section of the node menu) with typed parameter rows (name / type / default, `+ param` and per-row remove buttons, names validated and kept unique), a Return Type selector and an editable Body code box. Its single output pin is **Callable** (new `PinType.CALLABLE`, soft orange): it wires wherever a callback argument is taken — `Array.append(...)`, `Callable`-typed parameters and variables — and pin compatibility rejects a lambda into an untyped int slot and a typed number into a callback (Variant stays the universal fallback). Bodies generate inline when written inline (`func(x: float) -> float: return x * 1.15`) and as correctly indented blocks when written multi-line; the layout the script used is the layout it regenerates with. Parsing rebuilds lambdas as nodes everywhere they appear: var declarations with multi-line bodies (nested blocks keep their relative indentation), lambda defaults in `Callable` variables, assignment statements whose block opens with a lambda (these used to stay opaque verbatim text — they now rebuild structured and regenerate byte-identically), lambdas as arguments of resolvable calls (`use(func(): pass)` wired past the target pin) and whole-statement calls with unknown signatures that carry a lambda (`modifiers.append(func(x: float) -> float: ...)`, rebuilt as a free-form Function Call with the lambda wired in). Variables with lambda defaults get no accessor controls; captured-variable renames reach into lambda bodies and parameter defaults; unwired lambdas are exempt from the unreachable-node pass. Model: `_split_lambda_head` / `_parse_lambda_value` / `_lambda_expr` / `_spawn_lambda_from_text` / `_maybe_wire_lambda` / `_convert_lambda_call` / `_convert_lambda_pin_values` / `set_lambda_prop` / `add_lambda_param` / `remove_lambda_param`; canvas: `lambda_action` signal, `_on_lambda_action`, live in-place field updates, undo/redo titles. Tests: new lambda_tests_cli.gd (122 checks).
- **Class Reference & Member nodes.** Classes and their members are now nodes: a **Class Reference** node (new `Kind.CLASS_REF`, indigo header) names an engine class, `class_name` script, Autoload singleton or `res://` script path with one typed Object output pin, and **member nodes** — Function Call nodes bound to a method, property, signal or constant of that class — register on it through an "add member" slot (steel-blue ownership wire, `PinType.MEMBER`, one slot row per member, re-wiring moves it; disconnecting only drops the association). The Reference selector chooses **Class** (statics / constants / constructors: `Test_class.describe()`), **Instance** (an "instance" input pin plus an Instance Source field, default `self`: `player.get_health()`; a wired source wins) or **Singleton** (an Autoload: `Player.get_health()`). A member with an empty target resolves it from its registered reference; an instance-level member against a class-mode reference is reported as a generation problem instead of generating a call that cannot run. New discovery registry `class_registry.gd` (ClassDB methods/properties/signals/constants with inherited flags, project `class_name` scripts, Autoloads, script paths; `register_class` / `register_member` / `register_provider` extension points). Node menu gains a **Classes** section plus member search (`Test_class.get_health`); dragging from a Class Reference's "add member" slot opens the menu pre-filtered to that class's members and spawning one wires + registers in one step. Parsed dotted calls that resolve to exactly one known class reconstruct as member + Class Reference and regenerate byte-identically. Model: `member_links`, `register_member` / `unregister_member` / `member_owner`, `_call_target_source`, member branches in `_call_expr` / `_apply_call_meta` / `sync_call_signature`, `_link_parsed_class_member`. Tests: new class_ref_tests_cli.gd (80 checks).

- **Setter and Getter are created like a Function — the Add Setter / Add Getter buttons are gone.** A Variable node no longer has any Setter / Getter controls. Generation, loading existing `set(v):` / `get:` blocks as nodes, and the verbatim code box for blocks with comments are unchanged. - **Fix: comparison nodes could show 3+ inputs.** The Add-Node menu's Equal (==), Not Equal (!=), Less (<), Greater (>), Less or Equal (<=) and Greater or Equal (>=) entries spawned chainable *Operator* nodes — a dynamic-input kind (growing `a + b + c`-style operand pins) — so a comparison ended up with a third operand slot and generated nonsense like `((a == b) == c)`. They now spawn the dedicated **Condition** node (titled e.g. "Condition >="): exactly two operand pins, one Boolean output, an operator selector, operands auto-typed by what is wired in. Hardened in the model as well: a comparison operator can never have dynamic inputs (`is_dynamic_input_node` refuses comparison operators, so wiring never opens a grow slot), and switching an Operator's operator to a comparison (the node's editable operator field) collapses it to exactly two operands — extra operand pins are removed and wires into them disconnected; switching back to a chainable operator restores the grow slot. - **Function editor: edit one function in isolation.** Double-click a function in the dock's Graphs / Functions list and the canvas becomes a focused editor for that function alone: every other node (header, variables, other functions) is hidden together with its wires, the view pans so the function's whole cluster — its own Error / Warning nodes included — fills the canvas, and a banner appears ("Editing function 'x' …") with a **◀ Full picture** button. Esc does the same. Purely display-level: the model, the generated code and the hidden nodes' session positions are never touched, so the full picture comes back exactly as it was (all wires restored, no re-layout). While focused, editing works as usual (values, wiring, spawning nodes — new nodes stay visible inside the focus, and Error / Warning nodes only appear for the edited function); clicking another function's dock row switches the isolation directly; clicking any other dock entry (variable, enum, signal, dictionary) leaves the focus and goes to it. Deleting the isolated function itself exits cleanly. - **All Error / Warning nodes visible at once.** The nodes were always all spawned and wired, but the canvas never panned to them: after a load they sat far outside the view (often beyond the right dock), so only one was ever on screen and the rest had to be hunted down by scrolling. After new Error / Warning nodes appear — and after every full graph layout while problems exist — the canvas now pans so every Error / Warning node together with the node it reports on is on screen at once (content centered when it fits, pinned to its top-left edge when it is larger than the view). It never pans when everything is already visible, so it does not fight the person's own scrolling, and a clean graph keeps the old "scroll to the Script Header" behavior. Verified in GUI mode: three broken functions land all three Error nodes on screen at once; fixing one removes only its node and does not move the view; Warning nodes behave the same.
- **All errors at once.** Godot 4.7's `GDScript::reload()` prints only the FIRST syntax (parse) error per compile (an open `TODO` in the engine), so a broken Code pin surfaced its syntax errors one at a time — fix one, the next appeared. The compile check now reveals the rest by itself: after a failing compile with a single captured error, it re-compiles a scratch copy with each reported line temporarily swapped for `pass` (indentation kept) and repeats until the scratch parses or nothing new appears, collecting every further error with its original line number. The original generated code is never modified, revealed errors are deduplicated by line + message, the pass is capped at 8 rounds and cached with the compile result. Normal (analyzer) errors already all appeared at once and are unchanged. Note: while a reveal pass runs, each round's first error is printed to the Output panel as before. Tests added to graph_diag_tests_cli.gd.
- **Fix: the Warning node never showed for real GDScript warnings.** Analyzer warnings (unused variable, integer division, shadowing, untyped declaration promoted by the project, ...) were silently lost: the engine sends them to the debugger only, never to a Logger, so the compile check captured parse / compile errors but no warnings and no Warning node was ever spawned. `graph_diagnostics.gd` now captures them by temporarily promoting the project's warning levels (`debug/gdscript/warnings/*`, only those the project reports) to ERROR for the duration of one throw-away compile — the parser then emits each warning as a parse error the logger records, tagged " (Warning treated as error.)" — and restores the levels immediately afterwards (in memory only, nothing written to disk; a warning the user disabled stays disabled). Warnings are checked only for otherwise-clean code (a script that does not compile shows its errors first) and are cached per generated code like the error pass. `analyze()` / `refresh_diagnostics()` are now coroutines (they await a couple of frames for the engine's deferred settings refresh); `graph_canvas.gd` queues concurrent refreshes and cancels on reset. Note: while the promoted compile runs, the warnings appear in the Output panel as "(Warning treated as error.)" script errors for that moment — the logger and the output share one engine switch, so this cannot be suppressed. Tests updated in graph_diag_tests_cli.gd.
